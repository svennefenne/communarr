Before you start

What you're building

The NUC sits at home without a screen. You set it up once with a keyboard and monitor, and after that you control it from your own computer over SSH. Hooden runs inside Docker, and a small HTTPS front door lets your friends reach it from anywhere.

YOUR FRIENDS
Phones, tablets, computers
Open the site in a browser, or install it as an app on their home screen.

hooden container · port 3000

You need

  • The NUC with RAM and an SSD (8 GB RAM and a 120 GB SSD is plenty)
  • A USB stick of 4 GB or more (it will be wiped)
  • A keyboard and a monitor (HDMI), for the install only
  • A network cable to your router (a server should be wired)
  • Your own computer (Windows, Mac or Linux) to SSH from
  • For HTTPS: a domain name (about €10 a year) and access to your router's settings

How to read the commands

Every command box says where to type it: a terminal on the computer you sit at, the NUC after you've connected with ssh, or the settings file /opt/hooden/.env. Copy the lines one at a time and press Enter after each.

YOUR COMPUTER
ssh nuc
ON THE NUC
docker compose ps
IN THE .env FILE
TZ=Europe/Stockholm
Swap in your own values

The examples use 192.168.1.50 for the NUC's address, fenne for your username on the NUC, and hooden.example.com for your domain. Replace them with yours everywhere you see them.

01
Keyboard and monitor plugged in

Prepare the NUC

STEP 1.1Make the install stick

  1. Download Ubuntu Server 26.04.1 LTS from ubuntu.com/download/server. The file is called something like ubuntu-26.04.1-live-server-amd64.iso.
  2. Write it to the USB stick with balenaEtcher (Windows, Mac, Linux) or Rufus (Windows). Pick the ISO, pick the stick, and click Flash or Start.

On Linux you can also use dd. Check the stick's name with lsblk first, because dd overwrites whatever disk you give it:

YOUR COMPUTER Linux · /dev/sdX is the USB stick
lsblk
sudo dd if=ubuntu-26.04.1-live-server-amd64.iso of=/dev/sdX bs=4M status=progress conv=fsync

STEP 1.2Set the NUC to switch itself back on

A server should come back by itself after a power cut. Plug the keyboard, monitor and network cable into the NUC, switch it on, and press F2 straight away to open the BIOS.

  1. Go to Power → Secondary Power Settings (on some versions it's under Advanced → Power).
  2. Set After Power Failure to Power On.
  3. Press F10 to save and exit.
Good to know

Leave Secure Boot as it is; Ubuntu works with it. The menus on the NUC7 are Intel's "Visual BIOS", so the names may differ a little from the ones above.

STEP 1.3Start the installer

  1. Put the USB stick in and switch the NUC on.
  2. Press F10 during start-up to get the boot menu, and pick the USB stick.
  3. In the menu that appears, choose Try or Install Ubuntu Server.
02
About 15 minutes

Install Ubuntu Server

The installer is text-only. Move with the arrow keys and Tab, tick boxes with Space, and continue with Enter on Done. The screens come in roughly this order:

ScreenWhat to choose
Language, keyboardYours. If it offers an installer update, take it.
Type of installationUbuntu Server (not the "minimized" one, which leaves out tools you'll want).
NetworkThe wired connection should already have an address, such as 192.168.1.50/24. Write it down. If it says "disabled", check the cable.
Proxy, mirrorLeave as they are.
StorageUse an entire disk, pick the NUC's SSD, and keep Set up this disk as an LVM group ticked. On the summary, choose Done, then Continue to confirm. This wipes the disk.
ProfileYour name, a server name such as nuc, a username (lowercase, such as fenne) and a good password. You'll use the password for sudo.
Ubuntu ProSkip for now.
SSHTick Install OpenSSH server. This is what lets you control the NUC from your computer. If your SSH key is on GitHub, you can import it here (Import SSH key → from GitHub → your GitHub username) and skip step 4.2.
Featured server snapsPick nothing, and especially not docker. Part 05 installs Docker's own packages, which work better with Hooden's setup.
InstallingWait until it says Reboot Now, choose it, and pull out the USB stick when it asks.
Done when

The NUC restarts into a black screen with a login prompt such as nuc login:. Log in with your username and password to check that it works.

03
Still at the NUC's keyboard

First boot

STEP 3.1Find and fix the NUC's address

This shows the NUC's network address (the number before the /):

ON THE NUC at the keyboard
ip -br -4 addr
EXAMPLE OUTPUT
lo               UNKNOWN        127.0.0.1/8
eno1             UP             192.168.1.50/24

Your router hands out addresses and may give the NUC a different one later. To stop that, open your router's settings page, find the list of connected devices (look for nuc), and add a DHCP reservation (also called a static lease or fixed IP) for it with the address it has now. Every router names this differently.

STEP 3.2Bring Ubuntu up to date

ON THE NUC
sudo apt update && sudo apt full-upgrade -y
sudo reboot

Ubuntu installs security updates by itself after this (the unattended-upgrades service is on by default).

STEP 3.3Give the system the whole disk

The installer may give the system only part of the SSD. Check for unused space:

ON THE NUC
sudo vgs

If the VFree column shows more than a few GB, give it to the system, then check that / is now the size of the SSD:

ON THE NUC
sudo lvextend -r -l +100%FREE /dev/ubuntu-vg/ubuntu-lv
df -h /

STEP 3.4Optional: reach it by name

After sudo apt install -y avahi-daemon on the NUC, nuc.local works as well as 192.168.1.50 on most home networks.

Done when

You know the NUC's address, it's reserved in the router, and Ubuntu is up to date. From now on the NUC needs no keyboard or monitor; you can unplug them.

04
Back at your own computer

SSH from your computer

SSH gives you the NUC's command line from your own computer. Windows 10/11 (PowerShell), macOS (Terminal) and Linux all have it built in.

STEP 4.1Connect for the first time

YOUR COMPUTER
ssh fenne@192.168.1.50

The first time, it asks whether you trust the NUC's key. Type yes, then your password. To leave the NUC again, type exit.

STEP 4.2Log in with a key instead of a password

A key is safer than a password and saves typing. Skip this if you imported your key from GitHub during the install. Make a key (press Enter for the defaults; a passphrase is optional) and copy it to the NUC:

YOUR COMPUTER Linux and Mac
ssh-keygen -t ed25519
ssh-copy-id fenne@192.168.1.50
YOUR COMPUTER Windows PowerShell
ssh-keygen -t ed25519
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh fenne@192.168.1.50 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"

STEP 4.3A short name: ssh nuc

Add this to the file .ssh/config in your home folder (create it if it isn't there; on Windows it's C:\Users\<you>\.ssh\config):

YOUR COMPUTER ~/.ssh/config
Host nuc
    HostName 192.168.1.50
    User fenne

Now ssh nuc logs you straight in, and file copies work with the same name, such as scp nuc:backups/file.tgz .

STEP 4.4Turn off password logins

Once the key works (ssh nuc logs in without asking for the NUC password), stop SSH from accepting passwords at all:

ON THE NUC
printf 'PasswordAuthentication no\nKbdInteractiveAuthentication no\n' | sudo tee /etc/ssh/sshd_config.d/10-keys-only.conf
sudo sshd -t && sudo systemctl restart ssh

Test it from a new terminal window, keeping your current session open in case something went wrong. The first command should still log in; the second should be refused with Permission denied (publickey).

YOUR COMPUTER
ssh nuc
ssh -o PubkeyAuthentication=no nuc
Don't open SSH to the internet

Never forward port 22 in your router. To manage the NUC when you're away from home, use a private VPN such as Tailscale instead: install it on the NUC with curl -fsSL https://tailscale.com/install.sh | sh and then sudo tailscale up, install it on your laptop too, and ssh to the NUC's Tailscale name.

05
Over SSH from here on

Install Docker

STEP 5.1Install Docker Engine and Compose

Docker's own install script sets up its official packages, including docker compose, and starts Docker at every boot:

ON THE NUC
curl -fsSL https://get.docker.com | sudo sh

STEP 5.2Use Docker without sudo

ON THE NUC
sudo usermod -aG docker $USER
exit

Log in again (ssh nuc) so the change takes effect, then test it:

ON THE NUC
docker run --rm hello-world
docker compose version

You should see Hello from Docker! and a version number.

STEP 5.3Keep container logs from filling the disk

By default Docker keeps container logs forever. This keeps at most 3 × 10 MB per container. Do it now, because it only applies to containers created afterwards:

ON THE NUC
printf '{\n  "log-driver": "json-file",\n  "log-opts": { "max-size": "10m", "max-file": "3" }\n}\n' | sudo tee /etc/docker/daemon.json
sudo systemctl restart docker
About the firewall

Ubuntu's firewall (ufw) is off by default, which is fine behind a home router. If you turn it on, allow SSH first (sudo ufw allow OpenSSH, then sudo ufw enable), and for voice (part 08) also sudo ufw allow 3478 and sudo ufw allow 49160:49200/udp. Note that ports Docker publishes (3000, 80, 443) bypass ufw. To keep port 3000 off your network, use HOODEN_PORT=127.0.0.1:3000 as described in part 07.

06
The main event

Install Hooden

STEP 6.1Make a home for it and download the files

Everything lives in /opt/hooden: the Compose file that describes the containers, your settings in .env, and later the data folder.

ON THE NUC
sudo mkdir -p /opt/hooden
sudo chown $USER: /opt/hooden
cd /opt/hooden
B=https://raw.githubusercontent.com/svennefenne/hooden/main
curl -fLO $B/docker-compose.yml
curl -fLo .env $B/.env.example
mkdir -p deploy && curl -fLo deploy/Caddyfile $B/deploy/Caddyfile
id

The last command shows your user and group numbers, such as uid=1000(fenne) gid=1000(fenne). You need them next.

STEP 6.2Fill in the settings

ON THE NUC
nano .env

For the first start, only these three matter. Set them to your time zone and the numbers id showed:

IN THE .env FILE
TZ=Europe/Stockholm
PUID=1000
PGID=1000

Leave the lines starting with # for now; parts 07 and 08 turn them on. Save with Ctrl+O then Enter, and leave nano with Ctrl+X.

STEP 6.3Start it

ON THE NUC in /opt/hooden
docker compose up -d
docker compose logs -f hooden

The first start downloads the image (a few hundred MB). When the log shows [hooden] ready, press Ctrl+C to stop watching; Hooden keeps running. docker compose ps should then show the container as Up … (healthy).

STEP 6.4Create the admin account

  1. On your computer, open http://192.168.1.50:3000 in a browser.
  2. A fresh Hooden opens on the setup page. Pick the site's name and create your own account; it becomes the admin.
  3. Look around: Admin has the site's settings, members, invites, features and the look.
Invite your friends after HTTPS

Hooden is invite-only by default. You make invite links under Admin → Invites & sign-up. Set up HTTPS (part 07) first, so the links use your real address and work on phones.

Done when

You're logged in to your own Hooden at http://192.168.1.50:3000. It starts by itself after a reboot or a power cut.

07
So it works on phones, from anywhere

HTTPS

Phones only allow notifications, the microphone (voice chat) and installing a site as an app on secure https:// addresses. You need a domain name; then pick one of two ways. Both are already in Hooden's Compose file.

OPTION A · EASIEST

Cloudflare Tunnel

  • No router changes and no open ports
  • Works even if your internet provider shares your public IP (CGNAT)
  • Your domain must use Cloudflare's (free) DNS
  • Traffic goes through Cloudflare
OPTION B · DIRECT

Caddy

  • Traffic goes straight to your home
  • Caddy gets and renews the certificate itself
  • Needs ports 80 and 443 forwarded in your router
  • Doesn't work behind CGNAT

OPTION ACloudflare Tunnel

  1. Add your domain to a free Cloudflare account and change its nameservers at the registrar to the two Cloudflare gives you (or buy the domain from Cloudflare).
  2. In the Cloudflare dashboard, go to Zero Trust → Networks → Tunnels → Create a tunnel. Choose Cloudflared and name it hooden.
  3. On the connector page, choose Docker. The command it shows ends in --token eyJ…. Copy only the long token; don't run the command, because Hooden's Compose file runs the tunnel for you.
  4. Next, add a public hostname: subdomain hooden, your domain, service type HTTP, URL hooden:3000. Save. Cloudflare creates the DNS record itself.

Cloudflare moves and renames these menus now and then; a "public hostname" may be called a "published application route". Look for the same ideas.

IN THE .env FILE remove the # in front of these lines and fill them in
COMPOSE_PROFILES=tunnel
PUBLIC_URL=https://hooden.example.com
CLOUDFLARE_TUNNEL_TOKEN=eyJhIjoi…the whole token…
TRUSTED_IP_HEADER=cf-connecting-ip
HOODEN_PORT=127.0.0.1:3000   # optional: only reachable through the tunnel (and SSH)
ON THE NUC in /opt/hooden
docker compose up -d
docker compose logs cloudflared

Look for Registered tunnel connection, then open https://hooden.example.com.

OPTION BCaddy

  1. Find your home's public IP on the NUC with curl -4 ifconfig.me. In your domain's DNS, add an A record for hooden.example.com pointing at it. If your home IP changes now and then, use your router's dynamic DNS feature (or a service such as DuckDNS) and point a CNAME record at that name instead.
  2. In your router, forward TCP 80 and TCP + UDP 443 to 192.168.1.50.
IN THE .env FILE
COMPOSE_PROFILES=https
HOODEN_DOMAIN=hooden.example.com
PUBLIC_URL=https://hooden.example.com
HOODEN_PORT=127.0.0.1:3000   # optional: only reachable through Caddy (and SSH)
ON THE NUC in /opt/hooden
docker compose up -d
docker compose logs -f caddy

Wait for certificate obtained successfully, press Ctrl+C, and open https://hooden.example.com.

Is your IP shared? (CGNAT)

Compare the "WAN" or "internet" address on your router's status page with curl -4 ifconfig.me. If they differ, or the router's starts with 100., your provider shares your IP, and incoming connections never reach you. Use option A.

Changed .env? Use up, not restart

Settings in .env only apply when the containers are re-created, so always run docker compose up -d after editing it. docker compose restart keeps the old settings.

Phones and voice

STEP 8.1Install Hooden on a phone

PhoneHow
Android
Chrome		Open https://hooden.example.com and log in. Menu (⋮) → Add to home screen → Install.
iPhone, iPad
Safari		Open the address in Safari and log in. Share button → Add to Home Screen. From then on, open Hooden from the home-screen icon: iOS only allows notifications for sites added this way (iOS 16.4 or newer).

Then turn notifications on when Hooden asks, or in Hooden under Settings → Notifications. There you can also pick what to be notified about and set quiet hours.

STEP 8.2Voice chat on mobile data: a TURN server

Voice works out of the box on the same network and through most home routers. Phones on mobile data and strict networks need a relay, called a TURN server. Hooden's Compose file includes one (coturn). To set it up:

  1. Router: forward UDP + TCP 3478 and UDP 49160–49200 to 192.168.1.50.
  2. A name that reaches your home directly. With Caddy, use the same domain. With a Cloudflare Tunnel, add a DNS record turn (type A, your public IP) and set its proxy status to DNS only (grey cloud), because TURN can't go through the tunnel.
  3. A password: make one with openssl rand -hex 24 on the NUC.
IN THE .env FILE add turn to the profiles you already have
COMPOSE_PROFILES=tunnel,turn
VOICE_TURN_URL=turn:turn.example.com:3478
VOICE_TURN_USER=hooden
VOICE_TURN_PASS=the password you just made
VOICE_TURN_LAN_IP=192.168.1.50
ON THE NUC in /opt/hooden
docker compose up -d
docker compose logs coturn | grep -iE "relay address|external-ip|failed"

You should see Relay address to use: 192.168.1.50 and Whitelisting external-ip private part: 192.168.1.50. coturn looks up your public IP each time it starts. If the log says All providers failed, put your public IP in VOICE_TURN_PUBLIC_IP= and run docker compose up -d again.

If your home IP changes

Run docker compose restart coturn so it picks up the new address. To test, start a voice chat between someone on Wi-Fi at home and a phone on mobile data.

Connect with ssh nuc and go to the Hooden folder with cd /opt/hooden. Every command below runs there.

A good routine

  • Monthly: update Ubuntu and Hooden with the two commands above. If the login message says *** System restart required ***, run sudo reboot.
  • Now and then: check Admin → Overview in Hooden for activity and disk use, and Reports for anything members flagged.
  • Before big changes: take a backup (part 10).
Where things are

/opt/hooden/docker-compose.yml describes the containers; /opt/hooden/.env holds your settings; /opt/hooden/data holds everything Hooden stores: the database, uploaded pictures and its own backups. Those three are all you need to move Hooden to another machine.

10
Your friends' posts and pictures

Backups

Everything Hooden stores is in /opt/hooden/data. Stop Hooden for the few seconds it takes to pack it up, so the database is copied in a consistent state.

STEP 10.1A backup by hand

ON THE NUC in /opt/hooden
mkdir -p ~/backups
docker compose stop hooden
tar czf ~/backups/hooden-$(date +%F).tgz data
docker compose start hooden

The quickest alternative: Admin → System & backup in Hooden downloads a consistent copy of the database to your computer without stopping anything. It doesn't include the uploaded pictures.

STEP 10.2Every night, by itself

Open your scheduled tasks with crontab -e (choose nano if it asks) and add this as one line. It backs up at 04:30 and keeps two weeks of backups:

ON THE NUC crontab -e · one line
30 4 * * * cd /opt/hooden && docker compose stop hooden && tar czf $HOME/backups/hooden-$(date +\%F).tgz data; docker compose start hooden; find $HOME/backups -name 'hooden-*.tgz' -mtime +14 -delete

STEP 10.3Keep a copy somewhere else

A backup on the same NUC won't survive a broken SSD. Copy the backups to your computer, or a NAS, now and then:

YOUR COMPUTER
scp 'nuc:backups/hooden-*.tgz' .

STEP 10.4Restore a backup

ON THE NUC in /opt/hooden
docker compose down
mv data data.old
tar xzf ~/backups/hooden-2026-10-23.tgz
docker compose up -d

Once everything looks right, delete the old copy with rm -rf data.old. On a new machine, follow parts 02–06, then copy .env and a backup over and restore it this way.

When something's off

Troubleshooting

Start with docker compose ps and docker compose logs --tail 100 hooden in /opt/hooden. The log usually says what's wrong.

What you seeWhat to do
ssh: connection refused or timed outIs the NUC on, and is the address right? (Check ip -br -4 addr at the NUC.) If OpenSSH wasn't ticked during the install: sudo apt install openssh-server at the NUC's keyboard.
permission denied … docker.sockLog out and back in after step 5.2, so your user's new Docker group applies.
curl: (23) Failure writing outputYou don't own /opt/hooden: sudo chown $USER: /opt/hooden.
The page at :3000 doesn't loaddocker compose ps should say Up … (healthy). With HOODEN_PORT=127.0.0.1:3000, port 3000 is only open on the NUC itself, so use your https address, or ssh -L 3000:localhost:3000 nuc and http://localhost:3000.
port is already allocatedAnother program uses port 3000. Set HOODEN_PORT=3001 (for example) and run docker compose up -d.
Cloudflare shows 502 Bad GatewayThe tunnel's hostname must point at service type HTTP and hooden:3000 (not localhost). Check docker compose logs cloudflared and the token in .env.
Caddy gets no certificateThe A record must point at your public IP, and ports 80 and 443 must be forwarded to the NUC. Check for CGNAT (part 07). docker compose logs caddy says which step fails.
Invite links or calendar feeds use the wrong addressSet PUBLIC_URL in .env to your https address and run docker compose up -d.
No notifications on an iPhoneIt needs https, iOS 16.4 or newer, and Hooden opened from the home-screen icon (step 8.1), not from Safari. Then turn notifications on in Hooden's settings.
Voice works at home but not on mobile dataSet up TURN (step 8.2). Check the port forwards and the docker compose logs coturn lines.
Files in data belong to the wrong userSet PUID and PGID to what id shows, then docker compose up -d. Hooden fixes the owners as it starts.
The disk is filling updu -sh data ~/backups. Remove old backups and unused images with docker image prune -f. Admin → System & backup → Remove pictures nothing uses frees space too.
12
If you'd rather use your Unraid server

Unraid

Hooden comes with an Unraid template, so there's nothing to install on the command line.

  1. In Unraid, go to Docker → Add Container. Under Template repositories, add https://github.com/svennefenne/hooden and save.
  2. Pick Hooden from the template list.
  3. Check the values: the port (3000), Appdata (/mnt/user/appdata/hooden) and your time zone. It runs as 99:100 (nobody:users), Unraid's default.
  4. Apply, then open http://<your-unraid>:3000 and create the admin account.

For HTTPS, use what you already run on Unraid: SWAG, Nginx Proxy Manager (turn on Websockets Support) or the Cloudflare Tunnel container, pointing at http://<your-unraid>:3000. Then fill in Public URL in the template. A TURN server for voice can be set in the template's advanced view or in Hooden under Admin → Notifications & voice. The Appdata Backup plugin covers the data.

Updates: Unraid shows an update for the container when a new version is out. Apply it from the Docker tab.
